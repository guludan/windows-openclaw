# 优化2: Evidence质量门控 — 具体执行方案 v1.0

## 当前数据现状（5359条evidence）

| 类别 | 数量 | 占比 |
|------|------|------|
| 总evidence | 5359 | 100% |
| <30字 | 18 | 0.34% |
| <50字 | 121 | 2.26% |
| <100字 | 749 | 14.0% |
| 真正垃圾（标题/黑名单） | 2 | 0.04% |
| 有效短引用（<100字，有完整句意） | 664 | 12.4% |
| 边界情况（<100字，不确定） | 83 | 1.5% |

### 误杀风险评估
- 30字阈值：过滤18条，**全是有价值的短引用**（如"中苏关系恶化期间，对中国采取强硬态度，主张对中国使用核武器。"30字）
- 50字阈值：过滤121条，**全是有效的短引用**（如名人名言、关键陈述）

## 具体方案（三选一）

### 方案A: 硬门控（拒绝入库）
- 规则：长度<50字 → 拒绝入库
- 误杀：121条有效短引用被永久删除
- 适用：宁可放过不可错杀的反面——宁可错杀不可放过

### 方案B: 软门控（降权不拒绝）
- 入库时给每条evidence计算quality_score（0-1）
- 评分公式：
  ```
  quality_score = base_length_score + junk_penalty
  
  base_length_score:
    len >= 200:  1.0
    100 <= len < 200: 0.8
    50 <= len < 100:  0.6
    30 <= len < 50:   0.4
    20 <= len < 30:   0.2
    len < 20:          0.1
  
  junk_penalty（直接设为0）:
    - location包含"标题": quality_score = 0
    - 内容在黑名单(References等): quality_score = 0
    - 纯数字/章节号: quality_score = 0
  ```
- 检索时：在LanceDB的where条件中加 `quality_score >= 0.3` 过滤
- 好处：不丢失任何数据，但低质量evidence在检索中被降权
- 代价：需要给5359条已有evidence补算quality_score

### 方案C: 分层门控
- Tier 1（优质）：len >= 100 且 location不含"标题" → 正常检索权重
- Tier 2（可用）：50 <= len < 100 且 location不含"标题" → 检索时距离加0.1惩罚
- Tier 3（可疑）：30 <= len < 50 → 检索时距离加0.2惩罚
- Tier 4（拒绝）：len < 30 或 location含"标题" 或 黑名单 → 不入库
- 好处：分层精细，误杀最小
- 代价：实现复杂度中等

## 需要讨论的问题

1. 50字阈值会误杀121条有效引用（占2.26%）。塞勒说误杀的"损失厌恶"效应很严重。但津巴多说系统层面要让错误不可能发生。哪个优先？
2. 软门控的quality_score计算公式是否合理？长度和质量的关联性强吗？
3. 真正的垃圾只有2条（之前已清理过大部分）。是否还有必要加门控？
4. 边界情况83条（如戴笠的名字别名列表、古德里安的政治评价提示语），这些算有效evidence还是噪音？
